● 数据质量分析                                                                                                                                       
                                                                             
  我采样了500个episode、约1500帧的CoT数据进行统计分析：                                                                                              
                                                                                                                                                     
  各字段概况              
                                                                                                                                                     
  ┌────────────────┬────────┬───────────┬────────────┬─────────────────────────────────┐
  │      字段      │ 空值率 │ 平均长度  │ 帧间变化率 │            内容性质             │                                                             
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤                                                           
  │ task           │ 19.3%  │ 47 chars  │ 53%        │ 静态为主，整体任务目标          │                                                             
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤
  │ plan           │ 19.4%  │ 96 chars  │ 43%        │ 静态为主，分步计划              │                                                             
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤                                                             
  │ bboxes         │ 19.7%  │ 178 chars │ 87%        │ 动态，物体检测描述              │                                                             
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤                                                             
  │ subtask_reason │ 19.7%  │ 81 chars  │ 90%        │ 动态，解释"为什么选这个subtask" │                                                             
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤                                                             
  │ subtask        │ 19.6%  │ 24 chars  │ 90%        │ 动态，当前子任务                │                                                             
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤                                                             
  │ move_reason    │ 18.9%  │ 67 chars  │ 90%        │ 动态，解释"为什么朝这个方向"    │                                                             
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤                                                             
  │ move           │ 18.5%  │ 12 chars  │ 83%        │ 动态，移动方向                  │
  ├────────────────┼────────┼───────────┼────────────┼─────────────────────────────────┤                                                             
  │ gripper        │ 18.5%  │ 46 chars  │ 90%        │ 动态，夹爪5个关键点坐标         │                                                             
  └────────────────┴────────┴───────────┴────────────┴─────────────────────────────────┘                                                             
                                                                                                                                                     
  ▎ 空值率 ~19% 主要来自约 18.5% 的帧完全没有任何 CoT 标注，而非单个字段缺失。有 CoT 的帧中绝大部分是 8 个字段全的。                                 
                                                                
  关键发现                                                                                                                                           
                                                                
  1. 层级结构明显，存在信息冗余：                                                                                                                    
                                                                
  task (47 chars) → plan (96 chars) → subtask_reason (81 chars) → subtask (24 chars)                                                                 
                                                                → move_reason (67 chars) → move (12 chars)                                           
                                     → bboxes (178 chars)                                   → gripper (46 chars)                                     
                                                                                                                                                     
  - plan ⊃ subtask：subtask 往往是 plan 中某个步骤的直接摘取（word overlap 30%），层级冗余                                                           
  - subtask_reason ↔ subtask：reason 是解释性语言，word overlap 仅 17%，内容互补但语义重叠                                                           
  - move_reason ↔ move：move 只是一个方向词（如 "move up"），reason 是完整句子，word overlap 为0%，但 reason 信息密度低                              
                                                                                                                                                     
  2. bboxes 质量堪忧：                                                                                                                               
  - 是最长的字段（178 chars），但标注质量不一致："a blue plastic fork the fork"、"a piece the che" 等混乱描述                                        
  - 物体名称冗余重复，边界框坐标是否正确难以验证                                                                                                     
  - 这是信息密度最低的字段                                      
                                                                                                                                                     
  3. gripper 与 action label 的关系：                                                                                                                
  - CoT gripper = 5个关键点 [x1,y1,...,x5,y5]（空间位置）                                                                                            
  - Action label 的 gripper 维度 = 开合度（0~1）                                                                                                     
  - 两者不同，CoT gripper 提供了夹爪在图像空间中的位置，但此信息也可以从视觉特征中隐式学习                                                           
                                                                                                                                                     
  4. task 和 plan 是静态字段（43-53%的episode内不变），它们提供的是 episode 级的高层上下文，而非帧级指导

  消融实验建议

  ┌──────────┬─────────────────────────────────────────────────┬──────┬─────────────────────────────┬───────────────────────────────────────────┐

  ├──────────┼─────────────────────────────────────────────────┼──────┼─────────────────────────────┼───────────────────────────────────────────┤    
  │ Baseline │ 全部8个                                         │ 8    │ -                           │ 基准对照                                  │ 
  ├──────────┼─────────────────────────────────────────────────┼──────┼─────────────────────────────┼───────────────────────────────────────────┤    
  │ A        │ task, plan, bboxes, subtask_reason, subtask,    │ 7    │ gripper                     │ gripper                                   │    
  │          │ move_reason, move                               │      │                             │ 是空间关键点，图像可能已编码此信息        │    
  ├──────────┼─────────────────────────────────────────────────┼──────┼─────────────────────────────┼───────────────────────────────────────────┤    
  │ B        │ task, plan, bboxes, subtask, move               │ 5    │ 两个reason + gripper        │ 去掉"解释为什么"的冗余字段，保留"做什么"  │    
  ├──────────┼─────────────────────────────────────────────────┼──────┼─────────────────────────────┼───────────────────────────────────────────┤ 
  │ C        │ plan, bboxes, subtask, move                     │ 4    │ task + 两个reason + gripper │ 用户提议的组合，保留空间感知+规划链       │

  │ D        │ plan, subtask, move                             │ 3    │ task + bboxes + 两个reason  │ 极简，纯规划→执行链，测试最小编码是否足够 │    
  │          │                                                 │      │ + gripper                   │                                           │
  └──────────┴─────────────────────────────────────────────────┴──────┴─────────────────────────────┴───────────────────────────────────────────┘    
                                                                
  各组设计理由                                                                                                                                       
                                                                
  A (去gripper)：gripper 字段是5个关键点坐标                                                                                                         
  [x1,y1,...,x5,y5]，本质是low-level的空间信息，VLM的视觉编码器可能已经捕捉了夹爪位置。去掉它测试视觉特征能否替代显式关键点文本。
                                                                                                                                                     
  B (去两个reason+gripper，保留5个核心)：                                                                                                            
  - subtask_reason 和 move_reason 解释"为什么"，但不提供新的"做什么"信息
  - 它们占了约 150 chars（81+67），但信息增量小                                                                                                      
  - 测试去掉解释性语言是否影响模型对任务的理解                  
                                                                                                                                                     
  C (4字段，用户提议)：在B基础上再去掉 task。plan 已经包含分步计划，task 提供整体目标。测试 plan 是否已足够承载 task 的信息。                        
                                                                                                                                                     
  D (3字段，极简)：再去掉 bboxes（最长且质量最差的字段）。只剩 plan → subtask → move 三层执行链。如果这个效果接近 baseline，说明大量 CoT             
  文本是冗余的。                                                                                                                                     
                                                                                                                                                     
  如果资源有限，优先跑哪几组？                                                                                                                       
                                                    
  建议优先级：Baseline → B → D（3组），能覆盖"全量→中等简化→极简"的完整对比。如果效果差距明显，再补跑 A 和 C 定位具体是哪个字段的贡献。
